# 제품 정책

## 1. 제품 범위

하나의 Discord 통합 봇과 관리자 대시보드가 다음 기능을 제공합니다.

- 대화 요약
- 몰랭 검거
- KBO 경기 정보와 가상 크레딧 승부 예측
- 운영 설정 및 감사 로그
- 백업, 복구와 상태 확인

관리 대시보드의 운영 도메인은 `https://waw.dubeom.com`입니다.

KBO 기능은 2026-07-31 소유자 결정으로 제품 범위에 다시 포함합니다. 과거
`FUN-007`~`FUN-009`는 재사용하지 않고 새 요구사항 ID로 추적합니다.
KBO·스포츠투아이 또는 재허가 권한이 있는 계약형 공급자로부터 Discord와
대시보드 표시, 자동 접근, 저장과 필요한 보존 권리를 서면으로 확인하기 전에는
운영 데이터 수집과 승부 예측을 활성화하지 않습니다. 공개 웹 크롤링, 소비자
앱 내부 API와 다른 Discord 봇의 응답은 운영 데이터 공급원으로 사용하지
않습니다.

## 2. 공통 명령 정책

모든 명령 시도는 결과와 관계없이 기록합니다.

기록 대상:

- 성공
- 실패
- 권한 거부
- 입력 검증 실패
- 잘못된 채널
- 시간 초과
- 외부 API 실패
- 사용자 또는 시스템 취소

기록 금지:

- Discord 메시지 원문
- OAuth 인증 코드
- 액세스 및 리프레시 토큰
- 세션 비밀
- API 키
- 기타 비밀정보

로그는 누가, 언제, 어떤 명령을, 어느 범위에서 실행했고 결과가 무엇이었는지 확인할 수 있어야 합니다.

## 3. 대화 요약

- 사용자는 요약할 시간 범위를 지정합니다.
- 기본 입력은 최근 10분, 30분, 1시간, 3시간, 6시간, 12시간 또는
  24시간 중 하나를 Discord 선택 목록에서 고릅니다.
- 직접 입력은 `20:00`, `어제 23:30`, `오늘 00:30` 형식의 한국 시간
  (`Asia/Seoul`)을 사용합니다. ISO 8601 입력을 일반 사용자에게 요구하지 않습니다.
- 메시지 개수 제한 옵션을 사용자에게 요구하지 않습니다.
- 지정한 시간 범위 전체를 처리해야 합니다.
- 범위가 길면 계층적 요약을 사용할 수 있습니다.
- 처리 한계 때문에 일부 메시지를 조용히 제외해서는 안 됩니다.
- 전체 처리가 불가능하면 명확한 실패 또는 범위 조정 안내를 제공합니다.
- 원문 메시지를 영구 저장하지 않습니다.
- 등록 사용자에게 요약 실행 전 다음 외부 처리 경계를 대시보드와 도움말에
  상시 고지합니다.
  - 선택한 채널 또는 스레드의 최대 24시간 메시지를 OpenAI API로 전송합니다.
  - API 입력과 출력은 기본적으로 모델 학습에 사용되지 않습니다.
  - 안전성 모니터링을 위해 입력과 출력이 최대 30일 보존될 수 있습니다.
  - WAW는 메시지 원문과 생성된 요약을 영구 저장하거나 로그에 기록하지 않습니다.
- 결과에는 핵심 논의, 결정, 할 일과 미해결 질문이 구분되어야 합니다.
- `/요약`은 등록 사용자별 rolling 1시간에 한 번만 provider 호출을 예약합니다.
- 이 제한은 다른 명령이나 game observation에 적용하지 않습니다.

## 4. 몰랭 검거

몰랭은 등록된 사용자가 리그 오브 레전드 솔로 랭크를 플레이하면서 Discord Go Live 스트리밍 정책을 위반한 상황을 의미합니다.

- Twitch 스트리밍 여부를 기준으로 삼지 않습니다.
- 사용자는 Riot 계정을 등록할 수 있어야 합니다.
- 사용자가 연결을 요청하고 관리자가 승인한 활성 Riot 계정은 별도 계정별
  재동의 없이 자동 관측 대상이 됩니다. 연결 요청 응답과 도움말에서 이 사실을
  고지하고, 연결 해제 시 후속 관측 대상에서 제외합니다.
- 게임 시작과 종료를 자동 또는 수동으로 감지할 수 있어야 합니다.
- 게임 시작 직후 스트리밍 준비를 위한 유예시간을 둘 수 있어야 합니다.
- 짧은 스트림 중단을 허용하는 허용시간을 둘 수 있어야 합니다.
- 동일 사건을 중복 검거하지 않습니다.
- 자동 감지와 수동 신고를 구분합니다.
- 함께 플레이한 사람과 신고자를 기록할 수 있어야 합니다.
- 신고 신뢰도 또는 점수 정책은 관리자 설정으로 관리할 수 있어야 합니다.
- 오탐 정정과 관리자 취소가 가능해야 합니다.

구체적인 유예시간과 점수 계산식은 정책 설정값으로 정의하며 코드에 고정하지 않습니다.

## 5. KBO 경기 정보와 가상 크레딧 승부 예측

### KBO 경기 정보

- 현재 시즌 KBO 일정, 종료 경기 결과와 팀 순위를 Discord에서 조회할 수 있어야
  합니다.
- 응답에는 데이터 출처, 공급자 데이터 시각과 수집 시각을 구분해 표시합니다.
- 더블헤더와 재편성 경기는 공급자의 안정적인 경기 ID와 경기 차수로 구분합니다.
- 알 수 없거나 오래된 경기 상태를 정상 또는 최신 상태로 추정하지 않습니다.
- 공급자 장애, 지연 또는 권리 만료 시 새 베팅 접수는 실패 폐쇄하며, 권리
  미확인 경로로 자동 전환하지 않습니다.

### 가입과 크레딧

- 기존 `registered_discord_user` 등록은 승부 예측 가입으로 간주하지 않습니다.
- 사용자는 비현금성, 공개 랭킹과 데이터 처리 범위를 확인하고 별도로 가입해야
  합니다.
- 신규 가입자의 시작 잔액은 0 크레딧입니다.
- 가입 사용자는 `Asia/Seoul` 달력 날짜마다 직접 요청해 50,000 크레딧을 한 번
  받을 수 있습니다.
- 받지 않은 날짜의 크레딧은 누적하거나 소급 지급하지 않습니다.
- 크레딧은 현실 가치가 없으며 구매, 판매, 현금화, 외부 가치로의 환불, 양도,
  대여, 공동 사용, 상품·경품·역할·권한·광고·서비스 교환과 후원·구독·서버
  부스트 혜택 연계를 허용하지 않습니다.
- 화폐 기호나 “원”을 사용하지 않고 항상 “크레딧”으로 표시합니다.

### 승부 예측과 정산

- 사용자는 경기 시작 전 홈 승, 무승부 또는 원정 승을 선택하고 예상 점수를
  선택적으로 입력할 수 있습니다.
- 사용자·서버·공급자 경기 ID당 활성 베팅은 하나만 허용하며 첫 버전에서는
  등록 뒤 수정과 취소를 허용하지 않습니다.
- 베팅 등록 시 베팅액을 가용 잔액에서 즉시 차감합니다.
- 베팅액은 1,000 크레딧 단위의 양의 정수이며 최소 1,000, 사용자·경기당
  최대 50,000 크레딧입니다.
- 사용자별 `Asia/Seoul` 날짜당 접수 가능한 베팅 원금 합계는 50,000
  크레딧입니다. 같은 KST 날짜에 공식 무효가 확정되어 원금이 반환된 경우에만
  그 금액만큼 당일 한도를 복원하며, 지난 날짜의 한도를 소급 변경하지 않습니다.
- 관리자는 사용자별 한도 예외를 부여할 수 없습니다. 정책 한도 변경은 이미
  접수된 베팅에 소급하지 않습니다.
- 베팅액은 가용 잔액 이하여야 하며 가용 잔액은 음수가 될 수 없습니다.
- 결과 예측에 실패하면 반환액은 0배, 결과만 적중하면 원금을 포함해 2배,
  결과와 정확한 최종 점수를 모두 적중하면 원금을 포함해 3배입니다. 2배와
  3배를 합산하지 않습니다.
- 예정 시작 시각부터 베팅을 잠그며 시작 시각이나 경기 상태가 불명확하면
  접수를 거부합니다.
- 취소, 노게임과 연기는 베팅을 무효로 하고 원금을 반환합니다.
- 서스펜디드 경기는 공식 재개 또는 최종 판정까지 정산을 보류합니다.
- 공식 최종 결과는 정정 유예 상태를 거쳐 정산하며, 이후 기록 정정은 기존
  기록을 삭제하거나 덮어쓰지 않고 보상 원장 항목으로 처리합니다.
- 공식 정정 회수액이 현재 가용 잔액을 초과하면 가용 잔액은 0으로 유지하고
  초과분을 `correction debt`로 기록합니다. 이후 일일 50,000 지급, 당첨금과
  양수 정정액은 가용 잔액보다 debt 상계에 먼저 사용합니다.
- `correction debt`가 남아 있는 동안 새 베팅은 허용하지 않습니다.

### 사용자 조회와 랭킹

- 사용자는 가용 크레딧, 본인의 `correction debt`와 최근 5개 베팅의 경기,
  예측, 금액, 상태, 실제 결과와 반환액을 확인할 수 있습니다.
- 모든 서버 사용자는 가입 사용자를 대상으로 한 서버의 보유 크레딧, 결과 적중
  수, 정확 점수 적중 수와 적중률 랭킹을 조회할 수 있습니다.
- 무효 경기는 적중 횟수와 적중률 분모에서 제외합니다.
- 적중률 랭킹은 유효 정산 10경기 이상인 사용자만 순위에 포함하며 표본 수를
  함께 표시합니다.
- 공개 랭킹에는 내부 Discord ID를 노출하지 않고 서버 표시명과 필요한 통계만
  표시합니다.
- 보유 크레딧 랭킹은 시즌 초기화 없이 현재 `available_balance`를 사용하고
  `현재 보유 크레딧`으로 표시합니다.
- 결과 적중, 정확 점수 적중과 적중률 랭킹은 공급자의 안정적인 KBO
  competition/season ID를 기준으로 초기화합니다. 정규시즌과 포스트시즌은
  합치지 않고 완료 시즌을 별도 이력으로 제공합니다.
- 시즌은 공급자가 대회 종료를 확인하고 모든 관련 경기·베팅이 terminal일 때
  종료합니다. 이후 공식 정정은 이전 snapshot을 감사용으로 보존하면서 최신
  공식 revision의 과거 시즌 랭킹에 반영합니다.
- 동점은 공동 순위로 처리하고 안정적인 내부 정렬로 동점을 임의로 깨지
  않습니다.
- 보유 크레딧 랭킹에는 실제 가용 잔액에 반영된 관리자 조정분을 포함합니다.
  선택한 랭킹 범위에 관리자 조정 이력이 있으면 `관리자 조정 포함`만
  공개하고 조정액, 사유와 관리자 신원은 공개하지 않습니다.
- 관리자 조정은 결과 적중, 정확 점수 적중과 적중률의 분자·분모에 영향을
  주지 않습니다.

### 관리자 조회와 조정

- 관리자는 `https://waw.dubeom.com`에서 가입 사용자, 가용 잔액,
  `correction debt`, 일일 지급, 베팅, 정산·무효·정정, 랭킹, 관리자 조정과
  데이터 공급 상태를 조회할 수 있습니다.
- 관리자 크레딧 조정은 잔액 덮어쓰기가 아니라 부호 있는 불변 원장 항목으로
  기록하며 대상, 조정액, 필수 사유 코드, 실행 관리자, 조정 전·후 잔액, 시각과
  멱등 식별자를 보존합니다.
- 관리자는 자기 계정을 조정할 수 없고, 가용 잔액을 음수로 만드는 관리자
  차감은 거부합니다.
- 관리자 크레딧 조정은 `correction debt`를 직접 변경하거나 상계를 우회할 수
  없습니다.
- 대시보드 web process에 Discord bot token 또는 기능 테이블 직접 쓰기 권한을
  주지 않습니다. 조정은 별도 관리자 IPC의 명시적 허용 명령으로 처리합니다.
- 조정 직전 현재 관리자 역할, 15분 이내 OAuth, CSRF와 대상·금액·사유를
  표시한 명시적 확인을 모두 요구합니다.

### Discord 서버 탈퇴와 보존

- 사용자용 베팅 가입 해제 또는 복구 기능은 첫 범위에서 제공하지 않습니다.
- 사용자가 Discord 서버를 떠나면 즉시 새 일일 지급과 베팅을 거부하고 현재와
  과거의 모든 공개 랭킹에서 해당 사용자 행을 숨깁니다.
- 서버 탈퇴 당시 열린 베팅은 탈퇴를 이유로 무효화하거나 환불하지 않고 기존
  경기 정책에 따라 terminal 상태까지 정산합니다.
- 서버 탈퇴 처리를 원자적·내구적으로 기록한 뒤 표시명과 KBO 계정의 직접
  Discord user ID 연결을 제거합니다. 열린 베팅과 정산은 재연결할 수 없는
  opaque account ID로 계속 처리하며 별도의 복구·중복 가입 방지용 재연결
  토큰을 만들지 않습니다.
- Opaque 계정, 베팅·정산·정정·관리자 조정 원장과 최소 감사 기록은 서버 탈퇴
  시각과 마지막 KBO 원장 항목 시각 중 늦은 때부터 1년 보존합니다. 보존 중
  공식 정정과 `correction debt` 규칙은 그대로 적용합니다.
- 1년 뒤 법적 보존 의무나 진행 중 분쟁이 별도로 확인되지 않으면 사용자 단위
  opaque 계정·베팅·원장을 삭제하고 남은 `correction debt`도 함께 만료합니다.
  재식별할 수 없는 시즌별 총 가입자·총 베팅 같은 집계만 남길 수 있습니다.
- 서버에 다시 가입하더라도 과거 KBO 계정을 복구하거나 자동 연결하지
  않습니다. 다시 명시적으로 베팅에 가입하면 새 계정과 0 잔액에서 시작합니다.
- 운영 DB에서 제거한 직접 식별 연결은 30일 rolling backup에 최대 30일 더
  남을 수 있음을 가입 시 고지합니다. 만료된 backup은 제거하고 과거 backup
  복구 시 서버 탈퇴 상태와 연결 제거를 다시 적용합니다.

### 공개 전 법률·등급·Discord gate

- App Directory 등록, 공개 초대 링크, 두 번째 외부 서버, 불특정 다수 대상
  홍보 또는 공개 웹 가입 전에 다음 세 서면 증적을 모두 확보합니다.
  - 게임·도박·개인정보 분야 경험이 있는 한국 변호사의 구체 기능 검토
  - 게임물관리위원회의 게임물 해당 여부, 비영리 단순 공개 면제와 필요한
    등급·표시에 대한 사전 확인
  - Discord Developer Support 또는 App Review의 공개 배포와 필요한
    연령·등급 표시에 대한 정책 확인
- 무료·비현금 운영만으로 법률상 게임물, 비영리 면제 또는 등급을 자체
  확정하지 않습니다. Discord 확인은 한국 법률 검토를 대신하지 않고 법률
  검토도 Discord 정책 확인을 대신하지 않습니다.
- 세 확인 중 하나라도 불명확하거나 조건부이거나 거절되면 크레딧 예측 기능을
  공개하지 않고 공개 버전에는 KBO 일정·결과·순위 조회만 제공합니다.
- 크레딧 예측, 지급, 원장, 랭킹과 그 운영 커뮤니티는 Discord 구독, 서버
  부스트, 후원, 광고와 기타 수익화 대상에서 제외합니다.

## 6. 관리자 대시보드

대시보드는 다음 영역을 제공합니다.

### Overview

- 봇 연결 상태
- 최근 명령 상태
- 최근 오류
- 외부 서비스 상태
- 마지막 백업
- 몰랭 최근 현황
- KBO 데이터 공급과 미정산 경기 상태

### Logs

- 명령 감사 로그
- 오류 및 운영 이벤트
- 필터와 상세 보기
- 비밀정보와 메시지 원문 제외

### 몰랭

- 등록 사용자와 Riot 계정
- 진행 중 게임
- 검거 이력
- 오탐 정정
- 점수와 스택
- 감지 정책 설정

### KBO와 크레딧

- 가입 사용자와 가용 크레딧
- 일일 지급과 최근 베팅
- 경기 결과, 정산·무효·정정
- 크레딧·적중 랭킹
- 관리자 크레딧 조정과 감사
- 데이터 공급자 상태

### Settings

- 허용 채널
- 관리자 역할
- 요약 정책
- 몰랭 유예시간과 허용시간
- 데이터 보존 기간

### Operations

- 서비스 상태
- 외부 API 상태
- 백업 상태
- 수동 백업 및 복구 절차 안내
- 버전과 배포 정보

## 7. 접근 권한

- Discord OAuth를 사용할 수 있습니다.
- 허용된 Discord 서버의 승인된 운영자만 대시보드에 접근할 수 있어야 합니다.
- 읽기, 설정 변경, 복구 등 위험 수준에 따라 권한을 구분할 수 있어야 합니다.
- 중요한 설정 변경은 감사 로그를 남겨야 합니다.
