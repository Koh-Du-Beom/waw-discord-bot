# 제품 정책

## 1. 제품 범위

하나의 Discord 통합 봇과 관리자 대시보드가 다음 기능을 제공합니다.

- 대화 요약
- KBO 정보
- 몰랭 검거
- 운영 설정 및 감사 로그
- 백업, 복구와 상태 확인

관리 대시보드의 운영 도메인은 `https://waw.dubeom.com`입니다.

## 2. 공통 명령 정책

모든 명령 시도는 결과와 관계없이 기록합니다.

기록 대상:

- 성공
- 실패
- 권한 거부
- 입력 검증 실패
- 잘못된 채널
- 시간 초과
- 외부 API 실패
- 사용자 또는 시스템 취소

기록 금지:

- Discord 메시지 원문
- OAuth 인증 코드
- 액세스 및 리프레시 토큰
- 세션 비밀
- API 키
- 기타 비밀정보

로그는 누가, 언제, 어떤 명령을, 어느 범위에서 실행했고 결과가 무엇이었는지 확인할 수 있어야 합니다.

## 3. 대화 요약

- 사용자는 요약할 시간 범위를 지정합니다.
- 메시지 개수 제한 옵션을 사용자에게 요구하지 않습니다.
- 지정한 시간 범위 전체를 처리해야 합니다.
- 범위가 길면 계층적 요약을 사용할 수 있습니다.
- 처리 한계 때문에 일부 메시지를 조용히 제외해서는 안 됩니다.
- 전체 처리가 불가능하면 명확한 실패 또는 범위 조정 안내를 제공합니다.
- 원문 메시지를 영구 저장하지 않습니다.
- 결과에는 핵심 논의, 결정, 할 일과 미해결 질문이 구분되어야 합니다.

## 4. KBO

- 지정된 전용 채널에서 동작할 수 있어야 합니다.
- 경기 일정, 결과, 순위와 팀 관련 정보를 제공할 수 있어야 합니다.
- 데이터 출처와 갱신 시간을 표시해야 합니다.
- 출처 오류나 지연을 정상 데이터처럼 표시해서는 안 됩니다.
- 공급자 선택과 캐시 정책은 기술 조사 및 ADR로 결정합니다.

## 5. 몰랭 검거

몰랭은 등록된 사용자가 리그 오브 레전드 솔로 랭크를 플레이하면서 Discord Go Live 스트리밍 정책을 위반한 상황을 의미합니다.

- Twitch 스트리밍 여부를 기준으로 삼지 않습니다.
- 사용자는 Riot 계정을 등록할 수 있어야 합니다.
- 게임 시작과 종료를 자동 또는 수동으로 감지할 수 있어야 합니다.
- 게임 시작 직후 스트리밍 준비를 위한 유예시간을 둘 수 있어야 합니다.
- 짧은 스트림 중단을 허용하는 허용시간을 둘 수 있어야 합니다.
- 동일 사건을 중복 검거하지 않습니다.
- 자동 감지와 수동 신고를 구분합니다.
- 함께 플레이한 사람과 신고자를 기록할 수 있어야 합니다.
- 신고 신뢰도 또는 점수 정책은 관리자 설정으로 관리할 수 있어야 합니다.
- 오탐 정정과 관리자 취소가 가능해야 합니다.

구체적인 유예시간과 점수 계산식은 정책 설정값으로 정의하며 코드에 고정하지 않습니다.

## 6. 관리자 대시보드

대시보드는 다음 영역을 제공합니다.

### Overview

- 봇 연결 상태
- 최근 명령 상태
- 최근 오류
- 외부 서비스 상태
- 마지막 백업
- 몰랭 최근 현황

### Logs

- 명령 감사 로그
- 오류 및 운영 이벤트
- 필터와 상세 보기
- 비밀정보와 메시지 원문 제외

### 몰랭

- 등록 사용자와 Riot 계정
- 진행 중 게임
- 검거 이력
- 오탐 정정
- 점수와 스택
- 감지 정책 설정

### Settings

- 허용 채널
- 관리자 역할
- 요약 정책
- KBO 설정
- 몰랭 유예시간과 허용시간
- 데이터 보존 기간

### Operations

- 서비스 상태
- 외부 API 상태
- 백업 상태
- 수동 백업 및 복구 절차 안내
- 버전과 배포 정보

## 7. 접근 권한

- Discord OAuth를 사용할 수 있습니다.
- 허용된 Discord 서버의 승인된 운영자만 대시보드에 접근할 수 있어야 합니다.
- 읽기, 설정 변경, 복구 등 위험 수준에 따라 권한을 구분할 수 있어야 합니다.
- 중요한 설정 변경은 감사 로그를 남겨야 합니다.

## 8. 데이터

구체적인 DB 제품은 여기에서 결정하지 않습니다.

필수 요구사항:

- 일관성과 원자성
- 스키마 버전 관리
- 마이그레이션
- 자동 백업
- 복구 검증
- 내보내기 및 가져오기
- 참조 무결성
- 보존 기간
- 개인정보 최소 수집
- 향후 저장소 변경 가능성

## 9. 완료 기준

기능은 다음 조건을 모두 만족해야 완료입니다.

- 승인된 정책과 ADR에 부합
- 자동화 테스트 통과
- 실패 및 권한 경로 검증
- 로그에 민감정보가 없음
- 운영 및 복구 절차 갱신
- 관련 문서 갱신
