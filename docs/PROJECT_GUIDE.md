# 프로젝트 가이드

## 목적

이 문서는 프로젝트의 문서 체계와 개발 절차를 한눈에 안내합니다.

## 어떤 문서를 봐야 하는가

- 기능 요구사항이 궁금하면 `product/policy.md`
- 배포와 보안 요구사항이 궁금하면 `operations/deployment-and-security.md`
- Codex 작업 순서가 궁금하면 `ai/codex-workflow.md`
- 기술 후보와 검증 결과가 궁금하면 `research/`
- 기술 선택 이유가 궁금하면 `adr/`
- 실제 구현 순서가 궁금하면 `implementation/`
- 품질 규칙이 궁금하면 `standards/`
- Codex에 무엇을 요청할지 궁금하면 `prompts/`

## 상태의 의미

### Research

기술을 조사하고 비교하는 단계입니다. 제품 코드를 만들지 않습니다.

### Spike

문서만으로 판단할 수 없는 가설을 최소한의 폐기 가능한 코드로 검증합니다.

### Proposed ADR

추천안이 있지만 아직 프로젝트 결정으로 승인되지 않은 상태입니다.

### Accepted ADR

사용자가 승인하여 구현의 근거가 된 결정입니다.

### Implementation

승인된 ADR과 계획을 기반으로 작업을 하나씩 구현하는 단계입니다.

### Release

보안, 데이터, 운영과 롤백 조건을 확인하고 배포 가능 여부를 판단하는 단계입니다.

## 새 기능

1. 정책에 기능이 정의되어 있는지 확인
2. 새로운 기술 결정이 필요한지 판단
3. 필요하면 조사 및 Spike
4. Proposed ADR 작성
5. 사용자 승인
6. 구현 계획
7. 테스트 기반 구현
8. 리뷰
9. 문서와 변경 이력 갱신

## 버그

1. 재현
2. 영향 범위 확인
3. 회귀 테스트 작성
4. 최소 수정
5. 전체 관련 테스트
6. 문서 또는 운영 절차 갱신

## 기술 교체

1. 기존 ADR과 교체 조건 확인
2. 새 요구사항과 문제 정의
3. 후보 비교
4. 마이그레이션 및 롤백 검증
5. 기존 ADR을 대체하는 새 ADR 작성
6. 승인 후 단계적 전환
