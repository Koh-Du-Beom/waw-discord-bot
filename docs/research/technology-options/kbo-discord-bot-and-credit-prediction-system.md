# KBO Discord 봇 사례와 가상 크레딧 승부 예측 시스템 조사

- 상태: Research — 2026-07-31 `OWN-048` 재검토까지 반영
- 조사일: 2026-07-31
- 범위: KBO 조회 기능의 외부 사례·데이터 공급 경로와, 가상 크레딧 기반 승부 예측·랭킹·관리자 대시보드 요구사항
- 비범위: 구현, 외부 봇 초대, 데이터 공급 계약 체결, 법률 자문

## 요약 결론

1. KBO 일정·결과를 보여 주는 Discord 봇은 실제로 존재한다. **Sulyoon**은 많은 서버에서 사용되고 `/야구` 명령을 제공하므로 가장 현실적인 UX 비교 대상이다. **KBO Hub**는 KBO 전용 기능을 표방하지만 조사 시점에 오프라인이고 규모가 작다. 두 봇의 공개 초대 링크는 모두 Discord의 **Administrator** 권한을 요청하므로 운영 서버에 바로 초대하지 말고 별도 시험 서버에서만 검증하는 편이 안전하다.
2. 외부 봇은 화면·명령 UX의 블랙박스 참고 대상으로는 쓸 수 있지만, 데이터 공급처로 재사용하거나 응답을 수집하는 근거는 없다. 공개된 `kbo-game` 패키지도 KBO의 비공개 문서화된 계약 API가 아니라 웹사이트 내부 엔드포인트를 호출한다. KBO 이용약관은 사전 동의 없는 복제·제3자 제공을 제한하므로 생산 기능의 근거로 삼기 어렵다.
3. 생산 경로의 우선 후보는 **Discord 재배포 권리를 서면으로 확인한 계약형 스포츠 데이터 공급자**다. Sportradar Global Baseball API는 KBO 일정·결과·순위를 제공할 수 있는 유력 후보지만, 계약 범위·가격·Discord 표시권·정정 정책·가용성 보장은 아직 확인되지 않았다.
4. 조사 뒤 2026-07-31 소유자가 KBO 기능 재개와 비현금 크레딧 기본값을 승인했다. 제품 정책과 새 `FUN-021`~`FUN-031`에 반영하며 폐기된 `FUN-007`~`FUN-009`는 재사용하지 않는다.
5. “매일 5만원”은 현금 가치로 오해될 수 있다. 기능을 진행한다면 명칭을 **매일 50,000 크레딧**으로 고정하고, 구매·판매·현금화·양도·상품 교환·경품·후원/구독 혜택 연계를 모두 금지해야 한다. 이는 위험을 줄이는 제품 안전장치일 뿐 법률 판단을 대신하지 않는다.
6. 배당은 “베팅 원금을 먼저 차감하고 결과에 따라 총 0배/2배/3배를 반환”하는 방식으로 정의하는 것이 가장 일관된다. 정확한 점수 3배는 승패 적중 2배에 더하는 것이 아니라 이를 대체한다.
7. KBO에는 무승부, 더블헤더, 우천 취소, 서스펜디드 경기, 일정 변경과 공식 기록 정정이 있다. 이 상태들을 정의하지 않으면 정산 오류와 분쟁이 필연적이다.
8. 관리자 크레딧 조정은 잔액 덮어쓰기가 아니라 사유가 있는 불변 원장 항목으로 처리해야 한다. 현재 대시보드의 읽기 전용 DB 경계를 유지하고, 별도 관리자 명령 IPC를 통해 재인증·CSRF·확인·멱등성·감사를 거쳐야 한다.

2026-07-31 소유자가 KBO 일정·결과·순위와 비현금 크레딧 승부 예측을 다시
제품 범위에 포함하기로 결정했다. 과거 `FUN-007`~`FUN-009`는 이력 추적을 위해
재사용하지 않고 새 `FUN-021`~`FUN-031`을 사용한다.

현재 승인된 범위:

- KBO 기능의 제품 정책과 새 요구사항
- 비현금 50,000 크레딧, 3방향 예측과 0/2/3배 총 반환
- 경기당 사용자 베팅 하나와 별도 가입
- 불변 원장, 관리자 자기 조정 금지와 기존 관리자 IPC 확장 방향
- 데이터 공급·경기 상태와 원장 구조의 Accepted ADR

다음은 아직 승인 또는 실행되지 않았다.

- 구체 데이터 공급자 선정 또는 계약
- Discord 봇·대시보드 구현과 production 활성화
- 외부 봇을 실제 서버에 초대
- 생산 의존성 추가

시험 서버에서 사용할 수 있는 공개 Discord OAuth 링크는 [Sulyoon 초대](https://discord.com/oauth2/authorize?client_id=1390247647293603881&permissions=8&scope=bot+applications.commands)와 [KBO Hub 초대](https://discord.com/oauth2/authorize?client_id=1525428456966586538&permissions=8&integration_type=0&scope=bot+applications.commands)다. 링크를 열면 실제 추가 전 Discord 승인 화면이 나타나며, 조사 시점 두 링크 모두 Administrator 권한을 포함했다.

### 시험 서버에서 확인하는 방법

서버 소유자 또는 `Manage Server` 권한이 있는 사용자는 Discord 앱 초대 화면에서 봇을 추가할 수 있다. 다만 Sulyoon과 KBO Hub의 공개 OAuth 초대는 조사 시점에 `permissions=8`, 즉 Administrator 권한을 요청했다. Discord 문서상 Administrator는 모든 권한을 부여하고 채널별 제한을 우회하므로 운영 서버 평가에는 과도하다.

권고 절차는 다음과 같다.

1. 실제 사용자·웹훅·민감 채널이 없는 별도 시험 서버를 만든다.
2. 초대 승인 화면에서 봇 이름, 개발자, 요청 권한과 서버를 다시 확인한다.
3. 일정, 당일 결과, 순위, 우천 취소, 더블헤더, 무승부가 어떻게 표현되는지 수동으로 기록한다.
4. 같은 시점의 공식 KBO 페이지와 대조하되, 외부 봇의 응답을 자동 수집하거나 데이터 원천으로 사용하지 않는다.
5. 평가가 끝나면 서버에서 봇을 제거하고 Integrations 화면에서 남은 연동을 확인한다.

실제 초대는 외부 시스템 변경이고 Administrator 권한을 수반하므로 이 조사에서는 수행하지 않았다.

## 4. 공개 구현과 데이터 공급 경로

### 4.1 `kbo-game` npm 패키지

[`kbo-game`](https://www.npmjs.com/package/kbo-game)은 MIT 라이선스의 작은 오픈 소스 패키지다. 조사한 `0.0.2` 소스는 다음 내부 웹 엔드포인트에 요청한다.

`https://www.koreabaseball.com/ws/Main.asmx/GetKboGameList`

코드 검토 결과:

- KBO 웹사이트의 `Origin`과 `Referer`를 흉내 내 POST 요청을 보낸다.
- 일정·경기 상태·득점을 간단히 변환하며 런타임 의존성은 없다.
- 요청 타임아웃과 응답 스키마 검증이 없다.
- 알 수 없는 경기 상태를 예정 경기로 취급하고 점수 파싱 실패가 전파될 수 있다.
- 오류를 콘솔에 기록하므로 운영 로깅 정책과도 맞지 않는다.
- README 예시와 실제 export 이름이 일치하지 않는 부분이 있다.

MIT 라이선스는 패키지 코드 사용 허가일 뿐 KBO 경기 데이터의 복제·재배포 권리를 제공하지 않는다. KBO 이용약관은 서비스 정보를 사전 동의 없이 복제·출판하거나 제3자에게 제공하는 행위를 제한하고, 제휴 자료와 상업적 이용에 별도 동의를 요구한다. 이 패키지는 “기술적으로 호출 가능한 엔드포인트가 있다”는 가역적 조사 증거일 뿐 생산 데이터 공급 방안으로 권고하지 않는다.

### 4.2 공급 방안 비교

| 방안 | 장점 | 핵심 문제 | 판단 |
| --- | --- | --- | --- |
| 외부 Discord 봇의 출력 재사용 | 빠른 시연 | 재배포권·정확성·안정성 없음, 서비스 의존과 자동 수집 위험 | 제외 |
| KBO 웹사이트 또는 내부 엔드포인트 직접 수집 | 일정·순위가 공식 화면에 존재 | 이용약관상 자동 복제·제3자 제공 권한이 확인되지 않음, 비공개 스키마와 변경 위험, SLA 없음 | 동의 전 제외 |
| KBO와 직접 제휴 | 공식성과 권리 명확화 가능 | 협의 비용·기간·제공 형식·SLA 미확인 | 협상 후보 |
| 계약형 스포츠 데이터 공급자 | 구조화된 ID·상태·정정 피드 기대, 운영 지원 가능 | 계약 가격과 KBO/Discord 재배포 범위, 호출 한도, SLA를 서면 확인해야 함 | 우선 검토 |
| 관리자 수동 입력 | 작은 시험에 단순 | 휴먼 오류, 실시간성 부족, 정정·감사 부담 | 제한된 비생산 시험만 |

Sportradar Global Baseball API는 공식 개발자 문서에서 KBO를 Tier 1 대회로 다루며 시즌 일정·요약·순위 기능을 제공한다. 다만 문서에 KBO가 보인다는 사실만으로 Discord 서버에 원데이터 또는 가공 결과를 재배포할 권리가 생기지는 않는다.

계약 전 반드시 서면 확인할 항목:

- KBO 일정·라인업·실시간 점수·최종 결과·순위의 제공 범위
- Discord 봇과 `waw.dubeom.com`에 가공 데이터를 표시할 권리
- 캐시·저장 기간, 파생 데이터와 경기 ID의 보존 권리
- 호출 한도, 지연 시간, 가용성, 장애 통지와 지원 채널
- 취소·연기·서스펜디드·더블헤더·몰수·기록 정정의 상태 정의
- 계약 종료 시 데이터 삭제와 기존 베팅 감사 기록의 보존 가능 범위
- 가격, 시험 환경과 한국 내 이용 조건

## 5. 가상 크레딧 기능의 안전 경계

### 5.1 반드시 비현금형으로 정의할 것

사용자 표현인 “5만원”은 실제 원화 또는 경제적 가치로 오해될 수 있다. 기능 명세와 UI에서는 화폐 기호, “원”, 환율 또는 현금성 표현을 쓰지 않고 **50,000 크레딧**이라고 표시하는 방안을 권고한다.

허용하지 않을 항목:

- 현금 또는 암호자산으로 구매·판매·충전·환전·환불
- 사용자 간 송금, 선물, 거래, 대여 또는 공동 베팅
- 상품, 경품, 역할, 권한, 광고, 서비스와 교환
- Discord 구독·서버 부스트·후원·외부 결제 혜택과 연결
- 운영자 또는 사용자의 장외 매매·환전 중개

Discord Developer Policy는 불법 온라인 도박을 조장하거나 가능하게 하는 앱을 금지한다. Discord의 수익화 정책은 모의 카지노를 포함한 도박 또는 도박 인접 콘텐츠의 수익화를 제한한다. 대한민국 형법은 도박과 영리 목적의 도박 장소·공간 개설을 규정하고, 게임산업법은 게임 결과로 얻은 점수·게임머니의 환전·환전 알선·재매입을 제한한다. 스포츠 결과·점수 예측과 환전 가능한 게임머니가 결합된 사건에서 도박성이 인정된 판례도 있다.

따라서 위 경계는 필수적인 위험 저감책이다. 그래도 공개 서비스의 구체적 분류, 연령 등급과 운영 방식은 이 조사만으로 확정할 수 없다. 크레딧에 어떤 현실 가치라도 붙이거나 공개 범위를 크게 넓히기 전에는 한국 법률 자문과 Discord 정책 재검토가 필요하다.

### 5.2 권고 배당 정의

베팅 등록 시 원금을 즉시 가용 잔액에서 차감해 예치하고, 공식 정산 결과에 따라 아래 총 반환액을 지급한다.

| 결과 | 총 반환액 | 순손익 |
| --- | ---: | ---: |
| 승패/무승부 예측 실패 | `0 × 베팅액` | `-1 × 베팅액` |
| 경기 결과만 적중, 정확한 점수는 실패 또는 미제출 | `2 × 베팅액` | `+1 × 베팅액` |
| 경기 결과와 최종 점수를 모두 적중 | `3 × 베팅액` | `+2 × 베팅액` |
| 취소 등으로 무효 | `1 × 베팅액` | `0` |

정확한 점수 적중은 2배와 3배를 합친 5배가 아니라 3배가 최종 반환액이다.
이 총 반환액 해석은 `OWN-041`과 `ADR-0029`로 승인됐다.

### 5.3 중복 베팅 방지

한 사용자가 같은 경기의 양 팀에 같은 금액을 걸 수 있으면, 2배 총 반환 규칙에서는 한쪽 적중으로 원금을 모두 회수하면서 정확한 점수 보너스 기회도 얻는다. 이를 방지하려면:

- 사용자·서버·공급자 경기 ID당 활성 베팅은 하나만 허용한다.
- 가장 단순한 첫 버전은 등록 후 수정·취소를 허용하지 않는다.
- 수정이 필요하다면 경기 잠금 전 원베팅 환불과 새 베팅 차감을 한 트랜잭션에서 처리한다.
- 베팅액은 양의 정수이고 가용 잔액 이하여야 하며, 잔액은 음수가 될 수 없다.
- `OWN-044`에 따라 1,000 단위의 최소 1,000, 사용자·경기당 최대 50,000,
  KST 사용자 일일 원금 합계 최대 50,000을 적용한다. 같은 KST 날짜에 공식
  무효 환불된 금액만 당일 한도를 복원한다.

## 6. 승인된 경기 규칙과 남은 측정값

### 6.1 무승부

공식 KBO 순위에는 무승부가 존재한다. 요구사항의 “승/패”만으로는 무승부 경기의 예측과 정산을 정의할 수 없다.

`OWN-041`에 따라 홈 승·무승부·원정 승의 3방향 결과를 선택한다. 무승부와
정확한 동점 스코어를 맞히면 3배, 무승부만 맞히면 2배로 정산한다. 무승부
전체 환불안은 채택하지 않았다.

### 6.2 잠금 시간

- 베팅은 공급자가 제공한 예정 시작 시각 직전에 잠근다.
- “실시간 상태가 아직 시작 전으로 보인다”는 이유로 예정 시각 이후 접수하지 않는다.
- 시작 시각 또는 경기 상태가 불명확하면 실패 폐쇄 방식으로 접수를 중단한다.
- 일정 변경은 기존 시장과 베팅을 무효·환불한다. 공급자의 새 revision에서
  미래 시작 시각을 검증하면 기존 베팅을 되살리지 않고 새 `market_version`을
  열 수 있다.

### 6.3 취소·연기·서스펜디드·정정

권고 상태 모델:

`scheduled/open → locked → in_progress → final_pending → settled`

예외 상태:

- `postponed`: 기존 시장을 무효·환불하고 검증된 새 일정은 새 시장으로 취급
- `suspended`: 공식 재개 또는 최종 판정을 기다리며 정산 보류
- `void`: 취소·노게임·무효 처리, 원금 반환
- `corrected`: 공급자 최종 기록 정정 후 보상 원장으로 재정산

최종 점수가 도착하자마자 즉시 지급하기보다 짧은 `final_pending` 유예 시간을 두고 공식 상태를 다시 확인하는 방안을 권고한다. 구체적 시간은 공급자 정정 특성과 운영 SLA를 측정한 뒤 결정한다. 이미 정산한 내역은 삭제하거나 덮어쓰지 않고, 역분개와 재지급 원장 항목으로 수정해야 한다.

### 6.4 경기 식별

날짜와 팀 이름만으로 경기를 식별하면 더블헤더와 재편성 경기에서 충돌한다. 공급자가 보장하는 안정적인 경기 ID를 기준으로 하고, 더블헤더 차수·시즌·경기 종류를 함께 저장해야 한다.

## 7. 일일 크레딧과 사용자 등록

권고 규칙:

- 시작 잔액은 0 크레딧이다.
- 사용자가 `/크레딧 받기`를 직접 실행해야 지급한다.
- Asia/Seoul 기준 달력 날짜마다 50,000 크레딧을 한 번 지급한다.
- 놓친 날짜의 지급분은 누적되지 않는다.
- `(guild_id, user_id, claim_date)` 유일 제약과 원장 멱등 키로 중복 지급을 방지한다.
- 명령 처리, 지급 기록, 원장 반영은 한 DB 트랜잭션에서 수행한다.

현재 `registered_discord_user`는 Discord 명령 감사 과정에서 자동 등록된다. 이는 사용자가 베팅 기능과 공개 랭킹에 동의했다는 뜻이 아니다. 별도의 명시적 `betting_enrollment`가 필요하며, 가입 시 공개 범위·비현금성·Discord 서버 탈퇴와 보존 정책을 안내해야 한다.

추천 명령 구조:

- `/베팅 가입`: 기능 동의 및 가입
- `/크레딧 받기`: 당일 수동 지급
- `/크레딧 내정보`: 가용 잔액과 최근 거래 요약
- `/야구 일정`, `/야구 결과`, `/야구 순위`
- `/베팅 경기`: 베팅 가능한 경기 조회
- `/베팅 예측`: 경기·예상 결과·예상 점수·금액 제출
- `/베팅 내역`: 최근 5개 베팅
- `/랭킹 크레딧`, `/랭킹 승패적중`, `/랭킹 정확점수`, `/랭킹 적중률`

최근 5개 기록에는 경기, 선택, 예상 점수, 베팅액, 상태, 실제 결과, 반환액을 표시한다. 대기·무효·정정 상태도 숨기지 않으며 공급자의 원본 응답이나 내부 오류 정보는 노출하지 않는다.

## 8. 랭킹 정책

“적중 랭킹”은 적중 횟수와 적중률 중 무엇인지 모호하다. 다음 네 종류를 분리하는 방안을 권고한다.

| 랭킹 | 정의 |
| --- | --- |
| 보유 크레딧 | 현재 가용 잔액 |
| 결과 적중 | 정산된 경기에서 홈 승·무·원정 승을 맞힌 횟수 |
| 정확 점수 적중 | 결과와 최종 점수를 모두 맞힌 횟수 |
| 적중률 | `(결과 적중 수 ÷ 유효 정산 베팅 수) × 100` |

무효 경기는 횟수와 적중률 분모에서 제외한다. 표본 한 경기의 100%가 장기
참여자를 압도하지 않도록 `OWN-045`와 `ADR-0029`에 따라 적중률 랭킹에는
최소 유효 정산 10건을 요구한다.

고정 배당과 매일 지급은 크레딧 총량을 지속적으로 늘리고, 잔액 순위가 실력보다 가입 기간과 활동량을 반영하게 한다. 이를 금융적 공정성이나 실제 배당으로 표현하지 말아야 한다. 장기 확장 시 다음을 검토할 수 있다.

- 시즌별 랭킹과 전체 누적 기록을 분리
- 시즌 시작 시 순위용 점수만 초기화하고 감사 원장은 유지
- 동점 순위 방식(공동 순위 또는 조밀 순위) 명시
- 적중률의 최소 표본 수와 표본 수 병기
- 관리자 조정분을 경쟁 순위에서 분리하거나 조정 사실을 명확히 표시

Discord 출력은 상위 10명과 본인 위치를 우선 표시하고 페이지 이동을 제공하는 것이 임베드 길이와 개인정보 노출을 줄인다.

## 9. 관리자 조정과 대시보드

### 9.1 조정 방식

관리자가 임의로 크레딧을 조정할 수 있다는 요구는 운영 복구에는 유용하지만 경쟁 순위의 신뢰를 훼손할 수 있다. 잔액을 직접 덮어쓰지 말고 다음 필드를 가진 불변 원장 항목을 추가해야 한다.

- 대상 서버·사용자
- 부호 있는 조정액
- 필수 사유
- 실행 관리자
- 요청 멱등 키
- 조정 전·후 잔액
- 생성 시각
- 관련 장애·지원 티켓 식별자(있는 경우)

숨은 지급이나 삭제는 허용하지 않는다. 관리자 자기 계정 조정 금지는
`OWN-042`와 `ADR-0029`로 승인됐다. 2인 승인은 첫 범위에 포함하지 않으며
도입하려면 별도 제품·관리자 권한 결정을 거친다.

### 9.2 기존 신뢰 경계와의 결합

현재 대시보드는 기능 데이터에 읽기 전용 접근을 사용한다. 이 경계를 유지하고 관리자 조정은 ADR-0017의 별도 Unix socket 관리자 명령 경로를 확장하는 것이 프로젝트 구조와 가장 잘 맞는다.

조정 요청에는 최소한 다음이 필요하다.

- 현재 `guild_id` 범위와 관리자 역할 재확인
- 최근 OAuth 인증
- CSRF 방어
- 대상·금액·사유가 보이는 명시적 확인 화면
- 요청 멱등성
- 명령 결과와 감사 로그의 원자적 기록
- 웹 프로세스에 Discord bot token 또는 기능 테이블 직접 쓰기 권한을 부여하지 않음

이 확장은 새로운 고위험 관리자 변경 명령이므로 승인된 `ADR-0029`의 exact
IPC command를 따르며, 향후 구현 계획에서 별도 bounded task로 다뤄야 한다.

### 9.3 `waw.dubeom.com` 조회 범위

관리자 화면의 최소 읽기 범위:

- 가입 사용자와 현재 잔액
- 일일 지급 이력
- 베팅 목록과 상태, 예상/실제 결과, 반환액
- 정산·무효·정정 이력
- 크레딧·결과 적중·정확 점수·적중률 랭킹
- 관리자 조정 이력
- 데이터 공급자 최근 성공 시각, 지연, 오류와 미정산 경기

생산 호스트는 정책에 따라 `https://waw.dubeom.com`으로 고정한다. 사용자용 웹 대시보드는 현재 요구사항에 포함하지 않고 Discord 명령만 제공하는 것이 최소 범위다.

## 10. 권고 데이터 모델과 불변 조건

구체적 스키마는 ADR·구현 계획 단계에서 확정하되 다음 개념이 필요하다.

- `betting_enrollment`: 서버별 명시적 가입, 서버 탈퇴에 따른 비활성 상태와
  약관 버전
- `kbo_game`: 공급자 경기 ID, 팀, 예정 시각, 상태, 최종 점수와 공급자 시각
- `credit_ledger`: 지급·베팅 예치·반환·환불·관리자 조정의 불변 증감 원장
- `daily_credit_claim`: KST 지급 날짜와 원장 항목 연결
- `kbo_bet`: 사용자 예측, 점수, 금액, 잠금·상태
- `bet_settlement`: 사용한 공식 결과 버전, 판정, 반환액, 정정 연결
- 선택적 `credit_account`: 빠른 조회용 현재 잔액 캐시

핵심 불변 조건:

- 잔액은 원장 합계와 일치하고 음수가 아니다.
- 한 경기·한 사용자에는 활성 베팅 하나만 존재한다.
- 베팅액 차감과 베팅 생성은 원자적이다.
- 정산 상태 기록과 반환액 지급은 원자적이고 멱등이다.
- 일일 지급은 KST 날짜당 한 번뿐이다.
- 관리자 조정에는 관리자·사유·결과 감사가 반드시 남는다.
- 공급자 결과 정정은 기존 기록을 삭제하지 않고 보상 항목으로 처리한다.

## 11. 개인정보·보존·사용자 보호

Discord 사용자 ID에 연결된 잔액·베팅 내역·성향은 개인과 연결 가능한 행동 데이터다. 개인정보보호법의 최소 수집과 목적 달성 후 파기 원칙을 반영해야 한다.

현재 승인 정책:

- 공개 랭킹 참여를 베팅 가입 안내에 명확히 표시하고 명시적 가입 계정만 포함
- 공개 화면에는 Discord ID가 아니라 현재 서버 표시명과 필요한 통계만 노출
- 운영 로그에 Discord 메시지 내용, OAuth 코드, 세션 식별자, 토큰을 기록하지 않음
- Discord 서버 탈퇴 즉시 공개 랭킹에서 제외하고 표시명·직접 Discord 연결을
  제거하되 열린 베팅은 opaque account로 정상 정산
- 현재 프로젝트의 감사 보존 정책과 베팅 원장 보존 목적을 구분
- 데이터 공급 원문은 필요한 필드만 투영하고 계약상 보존 기간을 준수
- 손실 추격을 유도하는 알림, 과도한 긴급감과 반복 지급 알림을 사용하지 않음

## 12. 운영·비용·유지보수·마이그레이션

- **운영:** 수집 작업과 정산 작업을 분리하고, 마지막 성공 수집 시각·공급자 데이터 시각·미정산 경기 수·정정 횟수를 관측해야 한다. 공급자 장애 때 권리 미확인 웹 수집으로 자동 전환하지 않고 베팅 접수를 중단한다.
- **비용:** 단일 서버의 DB·웹 증분 비용보다 데이터 계약과 운영 대응 비용이 지배적일 가능성이 크다. 현재 공개 견적이 없어 프로젝트 월 지출 상한과 비교할 수 없다. 공급자 견적과 예상 경기/호출량 산정이 선행돼야 한다.
- **유지보수:** 공급자의 원본 스키마를 제품 전반에 퍼뜨리지 않고 필요한 경기 투영 모델만 둔다. 실제 두 번째 공급자가 생기기 전 범용 플러그인 계층을 만들지는 않는다.
- **공급자 종속성:** 내부에 공급자 경기 ID와 출처를 보존하되 팀·상태·시각을 정규화한다. 계약 종료 후 어떤 필드를 계속 보관할 수 있는지 먼저 확인한다.
- **마이그레이션:** 공급자 변경 시 경기 ID 대응표와 정산된 베팅의 기존 출처를 보존한다. 진행 중 경기와 열려 있는 베팅을 새 공급자로 자동 이동하지 않고 별도 검증·무효 정책을 적용한다.
- **롤백:** 읽기 기능은 오래된 데이터임을 표시하거나 닫고, 베팅 기능은 신규 접수를 잠근 뒤 열린 베팅을 공식 규칙에 따라 정산 또는 환불한다. 원장·정산·관리자 감사 기록은 기능 플래그를 꺼도 삭제하지 않는다.

## 17. 필요한 검증과 Spike

- Sulyoon과 KBO Hub의 실제 명령 출력, 취소·무승부·더블헤더 표시 방식
- SportsEye의 유효한 초대 경로
- Sportradar 또는 대체 공급자의 견적, KBO 범위와 Discord 재배포 조항
- 제공자의 경기 상태 코드와 공식 기록 정정 지연 분포
- 공개형 무료 스포츠 예측 기능의 국내 법률·게임 등급 적용 여부
- Discord 정책상 실제 구현·배포 형태에 대한 추가 제한

계약 후보가 생기기 전에는 데이터 코드 Spike를 하지 않는다. 먼저 KBO/스포츠투아이 또는 공급자에게 권리와 계약 조건을 서면 확인한다.

그 뒤 별도 승인된 가역적 Spike에서:

1. 한 시즌 일정, 10개 팀, 순위, 더블헤더와 안정적 경기 ID를 검증한다.
2. 무승부·취소·연기·서스펜디드·최종 정정 상태와 시각을 fixture로 보존한다.
3. 시작 전 잠금, 공급 지연 시 실패 폐쇄, 중복 요청과 재시작 후 멱등 정산을 시험한다.
4. trial 조건이 공개 표시를 금지하면 Discord에 게시하지 않고 로컬 합성 데이터로만 UI를 검증한다.
5. 별도 시험 서버에서 외부 봇의 명령 UX를 수동 비교하고 즉시 제거한다.

성공 기준은 권리의 서면 확인, 모든 핵심 경기 상태의 손실 없는 매핑, 중복 지급·이중 정산 0건, 장애 후 재처리 가능, 계약 비용 상한 충족이다.

## 18. 임시 추천과 가장 강한 대안

### 임시 추천

제품 범위, 비현금 안전 경계, 베팅 한도·랭킹·최소 서버 탈퇴 정책, 데이터
공급·경기 상태와 불변 원장·정산 ADR은 승인됐다. 다음 gate는 KBO 재배포
권리가 포함된 공급 계약, 신선도·정정 유예 실측과 법률·등급·Discord의 실제
서면 확인이다. 구현은 한 사용자·한 경기·한 베팅, KST 수동 일일 지급, 원금
선차감과 0/2/3배 총 반환, correction debt, 실패 폐쇄 잠금, 읽기 전용
웹+관리자 IPC를 따라야 한다.

### 가장 강한 대안

가장 강한 대안은 **KBO 또는 스포츠투아이와 직접 제휴하고 데이터 표시 범위를 최소화하는 것**이다. 상용 중간 공급자보다 권리 출처와 공식성이 명확해질 수 있고 제품에 필요한 일정·결과·순위만 받을 수 있다. 반면 계약 성사 가능성, 제공 형식, 비용, SLA와 기술 지원이 전혀 확인되지 않았으므로 현재 추천보다 실행 가능성이 낮다.

데이터 권리를 확보하지 못하더라도 커뮤니티 기능이 필요하다면, 실제 KBO 결과로 자동 정산하지 않는 수동 설문·응원 투표가 더 안전한 축소 대안이다. 다만 이는 요청한 크레딧 베팅 기능을 충족하지 않는다.

### 주요 위험

- 데이터 권리를 공개 API 존재와 혼동
- 가상 크레딧에 현실 가치가 생기며 법률·Discord 정책 위험이 급증
- 무승부·일정 변경·정정으로 잘못 정산
- 관리자 조정이 랭킹 신뢰를 훼손
- 서버 탈퇴 뒤 직접 연결 제거가 backup 복구에서 되살아남
- 계약 비용 또는 운영 부담이 개인 서버 규모를 초과

## 19. 되돌림 조건

다음 중 하나라도 충족되면 구현을 시작하지 않거나 기능을 중단해야 한다.

- KBO 데이터의 Discord 표시·저장 권리를 확보하지 못함
- 공급자가 안정적인 경기 ID, 최종 상태와 정정 정보를 제공하지 못함
- 크레딧에 구매·판매·양도·교환 또는 현실 가치가 추가됨
- Discord 정책 또는 법률 검토에서 배포 방식이 허용되지 않음
- 관리자 조정과 정산을 원자적 원장·감사로 구현할 수 없음
- 무승부·연기·취소·정정 정책에 오너 합의가 없음
