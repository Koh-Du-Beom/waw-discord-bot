# 외부 플랫폼 조사 통합 검토

- 상태: Research review
- 검토일: 2026-07-20
- 범위: Discord, Riot, KBO, 대화 요약 API 조사 문서의 교차 정합성 및 요구사항 추적성
- 비범위: 기술 선택, ADR 작성·승인, Spike 실행, 외부 문의·계정 신청, 제품 코드 구현

## 통합 판정

외부 플랫폼 가능성 조사 D-02는 **문서 조사 범위에서 완료**되었다. 네 문서 사이에 특정 기술을 즉시 배제하거나 정책을 서로 다르게 확정한 직접 충돌은 없다. 다만 다음 단계 전에 소유자가 정해야 하는 제품 계약 7건과, D-03에서 공통으로 모델링해야 하는 요구사항 공백이 남아 있다.

- Discord는 메시지 조회, Go Live 관측과 guild/role 확인을 위한 공식 경로가 있으나 절대적 메시지 무누락, Go Live 지연과 권한 재검증 시간은 보장하지 않는다.
- Riot은 공식 계정 연결과 자동 감지 후보가 있으나 Production/RSO 승인 및 5분 시작·종료 감지는 미확정이다.
- KBO는 요구 데이터가 공개되어도 자동 수집·Discord 재표시 권리, 원천 갱신 시각과 30분 SLA가 확인되지 않았다.
- 요약 API는 처리 후보가 있으나 120초 지연, 한국어 요약 완전성, 공급자 보존 허용 범위와 실제 월 비용은 미확정이다.

따라서 기술 선택이나 ADR로 진행할 근거는 아직 부족하다. 아래 소유자 결정과 데이터 흐름·위협 모델을 먼저 완료해야 한다.

## 중복과 통합 기준

| 중복 영역 | 문서별 표현 | 통합 기준 |
|---|---|---|
| 메시지 전체 범위 | Discord 문서는 HTTP 페이지 수집과 동시 삭제·권한 변경 한계를 다루고, 요약 문서는 manifest와 부분 처리 실패를 다룬다. | Discord 수집 완전성과 모델 처리 완전성을 별도 단계로 추적한다. 어느 단계든 검증 실패 시 부분 결과를 성공으로 반환하지 않는다. |
| 원문 비영구 처리 | Discord 문서는 외부 inference의 정책 적합성을 미확인으로 두고, 요약 문서는 애플리케이션 임시 처리와 공급자 보존을 비교한다. | `PRI-001`의 애플리케이션 저장 금지는 확정 기준으로 유지한다. 외부 공급자 보존 허용 여부는 소유자 결정 전 확정하지 않는다. |
| 몰랭 판정 | Riot 문서는 게임 상태, Discord 문서는 `self_stream`을 각각 다룬다. 양쪽 모두 5분 감지와 중복·유실 검증을 요구한다. | `(platformId, gameId)` 게임 사건과 Discord voice-state 관측을 분리하고, D-03에서 시간축·재시도·중복 키를 결합한다. 한쪽의 미확인 상태를 정책 위반으로 간주하지 않는다. |
| 외부 장애 | 네 문서 모두 429, timeout, 지연 또는 불완전 데이터를 정상 성공으로 취급하지 않는다. | 공통 외부 호출 결과 분류, correlation ID, 재시도 예산과 안전한 실패를 D-03에서 정의한다. |
| 비용 상한 | 요약 문서는 AI 요청 비용을 계산하고 KBO·Riot 문서는 가격 또는 호출량을 미확인으로 둔다. | `OWN-005`의 월 3만 원은 서비스별 한도가 아니라 백업·도메인을 포함한 전체 신규 비용 상한으로 유지한다. |
| Spike 후보 | Discord와 Riot 문서가 Go Live 조사를 연속 작업으로 중복 제안하고, Discord 문서 자체에 Go Live Spike 후보가 이미 있다. | 추가 Discord Go Live 조사 문서를 만들지 않는다. 문서로 확인되지 않은 지연·복구만 향후 단일 Spike 후보로 합친다. |

## 상충하거나 경계가 다른 가정

### 1. 메시지 무누락의 의미

- 제품 정책은 지정 시간 범위 전체 처리를 요구한다.
- Discord 문서는 이미 삭제됐거나 권한상 보이지 않는 메시지까지 포함하는 절대 무누락은 보장할 수 없다고 확인한다.
- 요약 문서는 수집 중 삭제·편집·권한 변경이 있으면 명시적으로 실패한다고 가정한다.

이는 직접적인 사실 충돌은 아니지만 성공 계약의 경계가 다르다. 접근 가능했던 메시지 집합을 요청 시점에 완전한 스냅샷으로 고정할 수 없으므로 ODR-001 없이는 `FUN-004`의 검증 기준을 만들 수 없다.

### 2. 120초 완료 범위

- 요약 문서는 Discord 수집부터 최종 검증까지 120초 전체 deadline으로 해석한다.
- Discord 문서는 실제 channel/thread/message 수에서 수집만으로 목표를 만족하는지 미확인으로 둔다.

`OWN-003`은 현재 “완료 목표 2분”이므로 전체 사용자 요청의 wall time으로 해석하는 것이 가장 보수적이지만, 소유자 확인 전 정책으로 확정하지 않는다.

### 3. 외부 공급자 보존

- `PRI-001` 원문 비영구 저장은 애플리케이션 DB·파일·로그에는 명확하다.
- 요약 API의 기본 안전성 보존을 같은 금지에 포함하는지는 문서마다 확정하지 않았다.

허용 범위에 따라 일반 API 후보가 유지되거나 ZDR 가능 후보만 남으므로 기술 선택 전 ODR-003이 필요하다.

### 4. KBO 30분의 시작 시점

KBO 문서는 “공급자가 공식 경기 종료 상태를 기록한 시점”부터 30분으로 가정한다. 사용자가 체감하는 실제 경기 종료 시점부터 계산하면 더 엄격하고 공급자 원천 지연을 숨길 수 없다. `OWN-006`의 측정 시작점을 ODR-006으로 확정해야 한다.

### 5. 개인·비상업 서비스의 외부 승인 가능성

KBO 문서는 개인 비상업 서버를 가정하지만 그 사실이 재표시 권리를 주지 않는다고 본다. Riot 문서는 같은 규모가 Personal key에는 맞을 수 있지만 RSO에는 Production 승인이 필요하다고 본다. 두 가정은 충돌하지 않지만 “소규모이므로 승인된다”는 공통 전제로 사용할 수 없다.

## D-03 데이터 흐름·위협 모델 입력

소유자 결정과 무관하게 다음 요소는 다음 연구 문서에 포함할 수 있다.

1. Discord command → 권한 검사 → 메시지 페이지 수집 → 메모리/통제된 임시 처리 → 외부 요약 API → 결과 반환 → 원문·중간물 폐기 → 비민감 감사 이벤트
2. Discord OAuth → 단일 guild/role 재검증 → 세션 발급·폐기 → 관리자 작업 감사
3. Riot 계정 연결 → 최소 식별자 보존 → Spectator 관측 → Discord voice state 결합 → 유예/중단 시간 → 사건 확정·정정·익명화
4. KBO 공급자 → 권리·source timestamp 확인 → 수집·cache → freshness 판정 → 전용 채널 응답 또는 명시적 실패
5. 모든 외부 경계의 비밀, timeout, 429, 재시도, 중복 키, correlation ID와 안전한 실패
6. UTC 저장 시각, 공급자 발생·갱신 시각, 수집 시각과 KST 표시 시각의 분리

ODR-001~007 중 데이터 흐름의 모양을 바꾸는 항목은 결정 전 두 갈래로 표시해야 하며, 어느 후보도 확정 기술로 표현하지 않는다.
