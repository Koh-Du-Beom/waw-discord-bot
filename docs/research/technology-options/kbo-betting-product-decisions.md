- 상태: Research — 2026-07-31 `OWN-048` 재검토 반영
- 조사일: 2026-07-31
- 승인일: 2026-07-31

  가입 해제·서버 탈퇴, 식별정보·원장 보존, 공개 전 법률·등급 검토

소유자가 아래 기본값을 승인한 뒤 탈퇴 범위를 다시 검토했다. `OWN-046`은
대체됐고, 사용자용 베팅 탈퇴·복구를 제외한 최소 서버 탈퇴 정책을
`OWN-048`에 반영했다.

## 1. 확정된 전제와 이번 결정의 경계

이미 승인된 전제는 다음과 같다.

- 크레딧은 구매·판매·현금화·양도·교환할 수 없고 경품, 유료 역할, 서비스,
  후원·구독 혜택과 연결하지 않는다.
- 가입 사용자는 KST 날짜마다 직접 요청해 50,000 크레딧을 한 번 받고, 놓친
  날의 지급분은 누적되지 않는다.
- 홈 승·무승부·원정 승 중 하나를 예측하며 한 사용자·경기에는 활성 베팅
  하나만 허용한다.
- 베팅액을 먼저 차감하고 실패 0배, 결과 적중 2배, 정확 점수 적중 3배,
  무효 1배를 총 반환한다.
- 모든 크레딧 변화와 correction debt는 `ADR-0029`의 불변 원장과 가용 잔액
  projection을 따른다.
- 관리자 조정은 기존 exact 관리자 IPC를 거치며 잔액을 덮어쓰지 않고,
  관리자는 자기 계정을 조정할 수 없다.
- 자동 생성되는 `registered_discord_user`와 베팅·공개 랭킹 가입 동의는
  별개다.

이번 문서는 이 전제를 바꾸지 않는다. 특히 현실 가치 금지, correction debt
우선 상계와 공식 결과 정정은 베팅 한도나 탈퇴로 우회할 수 없다.

## 2. 최소·최대 베팅액과 일일 한도

### 2.1 권고안

- 최소 베팅액: **1,000 크레딧**
- 사용자·경기당 최대 베팅액: **50,000 크레딧**
- 사용자별 KST 날짜당 접수 가능한 총 베팅액: **50,000 크레딧**
- 모든 금액은 1,000 크레딧 단위의 양의 정수로 제한한다.
- 일일 한도는 베팅 건수가 아니라 그 KST 날짜에 접수된 베팅 원금 합계로
  계산한다. KBO 정규 일정의 경기 수와 더블헤더가 달라도 같은 규칙을 쓴다.
- 같은 KST 날짜 안에 공식 무효가 확정되어 원금이 반환된 경우에만 그 금액만큼
  당일 한도를 다시 사용할 수 있다. 날짜가 지난 뒤의 무효·정정은 과거 한도를
  소급 변경하지 않는다.
- 한도 변경은 기존 베팅에 소급하지 않고 새 베팅 접수부터 적용한다. 관리자가
  사용자별 예외 한도를 부여하지 않는다.

최소 1,000은 하루 지급액의 2%라서 작은 금액의 선택권은 남기면서 1크레딧
베팅과 원장·명령 스팸을 줄인다. 건당·일일 최대 50,000은 하루 지급액과 같은
단위라 설명하기 쉽고, 오래 모은 잔액을 하루에 전부 소진하거나 급격히 불리는
것을 제한한다. 사용자는 한 경기에 전액을 걸거나 여러 경기에 나눌 수 있다.

공식 무효의 당일 한도 복원은 사용자가 통제할 수 없는 우천 취소 때문에 다른
경기까지 베팅하지 못하는 문제를 줄인다. 반대로 패배·당첨·사용자 탈퇴와
관리자 조정은 한도를 복원하지 않는다.

### 2.2 가장 강한 대안

최소와 일일 총액은 그대로 두고 **건당 최대만 10,000 크레딧**으로 낮춘다.

이 안은 한 경기 all-in과 큰 단일 정산·정정의 영향을 줄이고, 하루 지급액을
여러 경기에 분산하게 한다. 반면 경기 수가 적거나 특정 경기만 예측하려는
사용자에게 불필요하게 답답하고, 50,000 이상의 잔액을 보유할 동기를 약하게
만든다.

### 2.3 배제할 안

- 가용 잔액의 일정 비율로 최대액을 계산하는 방식은 잔액이 큰 사용자를 더
  우대하고 사용자에게 설명하기 어렵다.
- 경기별로 관리자가 한도를 수동 변경하면 내부 정보나 임의 판단에 따른 공정성
  논쟁이 생긴다.
- 일일 한도를 베팅 건수로만 두면 한 경기당 금액을 통해 한도를 사실상 우회할
  수 있다.
- 무제한 베팅은 일일 지급액, 공개 보유액 랭킹과 책임 있는 제품 경계를
  약화한다.

### 2.4 결정 시 함께 고정할 세부 규칙

1. `Asia/Seoul`의 서버 검증 시각으로 날짜를 계산한다.
2. 동시 제출은 모든 한도 검증과 원장 차감을 같은 직렬화 경계에서 판단한다.
3. correction debt가 남은 사용자는 잔액·한도와 관계없이 새 베팅을 할 수 없다.
4. 접수 후 사용자 취소나 금액·예측 수정은 첫 버전에서 허용하지 않는다.
5. 한도 거부 응답에는 현재 베팅 가능 잔여 일일 한도를 보여 주되 다른 사용자의
   정보는 노출하지 않는다.

## 3. 시즌 랭킹 초기화와 관리자 조정분

### 3.1 먼저 분리해야 하는 두 종류의 랭킹

`현재 보유 크레딧`은 계정의 현재 가용 잔액이고, `결과 적중`, `정확 점수
적중`, `적중률`은 경기 예측 성적이다. 잔액을 유지하면서 보유액 랭킹만
“초기화”하면 표시 순위와 실제 사용 가능한 금액이 달라진다. 반대로 시즌마다
실제 잔액을 0으로 만들면 크레딧의 시즌 만료라는 새 경제 규칙과 새 원장 사유가
필요하다.

### 3.2 권고안

#### 시즌 경계

- 공급자의 안정적인 KBO `competition/season` 식별자를 기준으로 정규시즌,
  포스트시즌과 다음 연도를 분리한다.
- **보유 크레딧 랭킹은 시즌 초기화하지 않고 현재 가용 잔액을 그대로
  순위화한다.** 화면에는 `현재 보유 크레딧`으로 표시해 시즌 성적으로
  오인하지 않게 한다.
- 결과 적중 수, 정확 점수 적중 수와 적중률은 **대회·시즌별로 0에서
  시작**한다. 포스트시즌은 정규시즌과 합치지 않는다.
- 완료된 시즌은 별도 이력으로 조회할 수 있고, 기본 화면은 현재 대회·시즌을
  보여 준다. 전체 기간 누적 적중 통계는 보조 화면으로만 제공한다.
- 시즌 종료는 날짜 추정이 아니라 공급자가 해당 대회의 종료를 확인했고 열린
  경기·베팅이 모두 terminal인 때로 정한다.
- 시즌 종료 뒤 공식 기록 정정이 오면 과거 정산과 랭킹도 새 revision으로
  다시 계산한다. 이전 snapshot은 감사용으로 남기고 사용자에게는 최신 공식
  revision과 갱신 시각을 보여 준다.
- 동점은 공동 순위로 처리한다. 안정적인 내부 정렬은 페이지 결과를 고정할
  뿐 동점을 임의로 깨지 않는다.

#### 관리자 조정

- 보유 크레딧 랭킹은 실제로 사용할 수 있는 `available_balance`를 표시하므로
  관리자 조정분도 포함한다.
- 선택한 랭킹 범위에서 관리자 조정 이력이 있는 계정에는 공개적으로
  `관리자 조정 포함`이라는 중립 표식을 붙인다. 조정액, 사유와 관리자 신원은
  관리자 대시보드에만 표시한다.
- 관리자 조정은 결과 적중 수, 정확 점수 적중 수, 적중률의 분자·분모를
  변경하지 않는다.
- 조정 사유는 오입력·장애 복구·정책상 보상처럼 허용된 사유 코드로만 남기고,
  공개 랭킹을 올리기 위한 조정은 운영 정책상 금지한다.
- correction debt와 그 상계는 관리자 조정이 아니며 공개 표식 대상도 아니다.
  Debt 자체는 기존 결정대로 공개 랭킹에 노출하지 않는다.

이 안은 “보유 크레딧”이 실제 잔액이라는 의미를 보존하고, 조정 사실을 숨기지
않으면서 개인적인 사유는 공개하지 않는다. 적중 랭킹은 관리자 조정과 완전히
독립적이다.

### 3.3 가장 강한 대안

**완전한 시즌제 경제**로 운영한다.

- 정규시즌 시작 때 모든 가입 계정의 가용 잔액을 0으로 만든 뒤 새 시즌
  지급을 시작한다.
- 잔액 삭제나 덮어쓰기가 아니라 별도의 `season_expiry` 불변 원장 항목으로
  만료액을 기록한다.
- 모든 보유액·적중 랭킹을 시즌별로 0에서 시작한다.
- 해당 시즌에 관리자 조정이 한 번이라도 발생한 계정은 그 시즌 보유액
  랭킹에서 제외한다. 적중 랭킹은 계속 포함한다.

시즌 간 출발선을 완전히 맞추는 가장 명확한 안이지만, 사용자가 모은 크레딧이
예고된 날짜에 소멸하고 `ADR-0029`에 없는 원장 사유와 만료 정책이 필요하다.
따라서 이 대안을 선택하려면 제품 정책 변경뿐 아니라 `ADR-0029`의 후속
architecture 결정도 필요하다.

### 3.4 배제할 안

- 실제 잔액은 유지하면서 화면의 “시즌 보유액”만 임의로 0에서 시작하면
  보유액과 사용 가능액이 다르므로 배제한다.
- 관리자 조정 사실을 아무 표시 없이 보유액 랭킹에 포함하면 운영자가 순위를
  만들었다는 의심을 검증하기 어렵다.
- 공개 화면에 조정 사유나 관리자를 노출하면 개인정보와 운영 보안 정보를
  과도하게 공개한다.
- 시즌 snapshot을 영원히 고정해 공식 정정을 무시하면 Accepted `ADR-0028`과
  `ADR-0029`의 정정 계약에 어긋난다.

## 4. Discord 서버 탈퇴와 원장 보존

### 4.1 재검토 결과

사용자용 베팅 가입 해제·복구는 KBO 핵심 기능이 아니므로 첫 범위에서
제외한다. 처리 대상은 Discord 서버 탈퇴 event뿐이다. 기존 `OWN-046`의
30일 복구, 가명 재연결 토큰과 기존 계정 복원은 채택하지 않고 `OWN-048`이
대체한다.

### 4.2 승인된 최소 정책

- 서버 탈퇴 즉시 새 일일 지급과 베팅을 거부한다.
- 현재·과거의 모든 공개 랭킹에서 해당 사용자 행을 숨긴다.
- 열린 베팅은 서버 탈퇴를 이유로 환불하지 않고 기존 경기 정책에 따라
  terminal까지 정산한다.
- 서버 탈퇴 처리를 원자적·내구적으로 기록한 뒤 표시명과 KBO 계정의 직접
  Discord user ID 연결을 제거한다.
- 열린 베팅·정산·정정은 재연결할 수 없는 opaque account ID로 계속 처리하고,
  복구나 중복 가입 방지를 위한 별도 재연결 토큰은 만들지 않는다.
- Opaque 계정과 사용자 단위 원장은 서버 탈퇴 시각과 마지막 KBO 원장 항목
  시각 중 늦은 때부터 1년 보존한다. 이 기간에는 공식 정정과 correction debt
  규칙을 그대로 적용한다.
- 1년 뒤 별도 법적 보존 의무나 진행 중 분쟁이 없으면 계정·베팅·원장과 남은
  debt를 삭제하고 재식별할 수 없는 시즌 집계만 남길 수 있다.
- 서버 재가입은 과거 계정 복구가 아니다. 사용자가 다시 명시적으로 베팅에
  가입하면 새 계정·0 잔액으로 시작한다.
- 직접 식별 연결은 운영 DB에서 제거해도 30일 rolling backup에 최대 30일
  남을 수 있다. 과거 backup 복구 뒤 서버 탈퇴 상태와 연결 제거를 다시
  적용한다.

### 4.3 명시적으로 수용한 tradeoff

- 서버를 나갔다 돌아온 사용자는 과거 잔액과 correction debt를 승계하지
  않는다. 이를 막기 위한 재연결 식별자를 보존하지 않는 것이 최소 정책의
  우선순위다.
- 탈퇴 뒤 사용자별 분쟁 대응은 직접 Discord ID가 아니라 보존 중인 opaque
  원장과 관리자 감사 범위로 제한된다.
- 과거 공개 랭킹 행을 숨기므로 당시 순위 화면이 현재 조회 시 달라질 수 있다.

### 4.4 대체된 안

다음 `OWN-046` 요소는 더 이상 현재 정책이 아니다.

- 사용자용 베팅 가입 해제
- 30일 계정 복구 유예
- 가명 재연결 토큰
- 서버 재가입 시 기존 잔액·debt 복구

## 5. 공개 전 법률·등급·Discord 검토

### 5.1 확인된 공식 경계

이 문서는 법률 의견이 아니며 서비스의 법적 분류를 확정하지 않는다. 확인된
공식 경계는 다음과 같다.

- 형법 제246조는 도박을 규정하고 일시오락 정도의 예외를 두며, 제247조는
  영리 목적으로 도박 장소나 공간을 개설하는 행위를 규정한다.
- 게임산업법 제21조는 이용에 제공할 게임물의 사전 등급분류를 원칙으로 하고
  비영리 제작·배급 게임물의 예외를 대통령령에 맡긴다. 시행령 제11조의3은
  개인·동호회 등이 국내에서 단순 공개를 목적으로 창작한 게임물을 규정하고,
  해당 여부를 게임물관리위원회에 미리 확인받을 수 있게 한다.
- 같은 법 제32조제1항제7호는 게임 이용으로 얻은 점수·게임머니 등 결과물의
  환전·환전 알선·재매입을 업으로 하는 행위를 금지한다.
- Discord Developer Policy는 API를 불법 온라인 도박에 사용하지 못하게 하고,
  법령이나 Discord가 요구하는 적절한 등급을 사용 전 명확히 표시하도록
  요구한다.
- Discord Monetization Policy는 Discord 수익화 기능에서 모의 카지노,
  도박 논의·조언과 도박 운영 커뮤니티 같은 도박·인접 콘텐츠의 수익화를
  허용하지 않는다.

비현금·비양도 크레딧과 비영리 운영은 중요한 위험 저감 장치지만, 이 Discord
봇이 법률상 게임물인지, 비영리 단순 공개 예외에 해당하는지, 어떤 등급이나
표시가 필요한지를 자동으로 확정하지 않는다.

### 5.2 권고 공개 gate

`공개`에는 App Directory 등록, 누구나 사용할 수 있는 초대 링크 배포, 두 번째
외부 서버 추가, 불특정 다수 대상 홍보와 공개 웹 가입을 포함한다.

다음 세 증적이 모두 문서화되기 전에는 크레딧 예측 기능을 공개하지 않는다.
공개 여부와 법률상 분류가 항상 일치하는 것은 아니므로, 소유자만 합성 데이터로
검증하는 시험을 제외한 실제 사용자 대상 비공개 활성화도 아래 1번과 2번
확인 전에는 하지 않는 안을 권고한다.

1. **한국 법률 검토**
   - 게임·도박·개인정보 분야 경험이 있는 한국 변호사의 서면 의견을 받는다.
   - 형법 제246조·제247조, 게임산업법상 게임물·사행성게임물·등급분류·비영리
     예외·게임머니, 개인정보 수집·랭킹 공개·탈퇴 보존을 구체 기능 설명에
     대입한다.
   - `현실 가치 없음`, 구매·판매·양도·경품·수익화 금지와 운영 서버 범위를
     사실관계로 명시한다.
2. **게임물관리위원회 사전 확인**
   - 시행령 제11조의3제3항 경로 또는 위원회가 안내하는 최신 공식 절차로,
     봇이 게임물인지와 비영리 단순 공개 면제 해당 여부를 서면 확인한다.
   - 면제가 아니라면 필요한 등급, 신청 주체와 Discord 프로필·명령 사용 전
     표시 방법을 확인한다.
   - “무료이므로 면제”라고 자체 판단하지 않는다.
3. **Discord 정책 확인**
   - Developer Support/App Review에 홈 승·무·원정 승 예측, 0/2/3배 비현금
     크레딧, 공개 랭킹, 구매·양도·교환·경품·수익화 금지를 정확히 설명하고
     공개 배포와 필요한 연령·등급 표시에 대한 서면 답변을 보존한다.
   - Discord의 답변은 한국 법률 의견을 대신하지 않고, 법률 의견도 Discord
     플랫폼 승인을 대신하지 않는다.

세 검토 중 하나라도 불명확·조건부·거절이면 공개를 중단하고 조건을 제품
정책과 화면에 반영한 뒤 다시 확인한다. 실제 이용자 대상 비공개 운영도 한국
법률·등급 확인 결과의 적용 대상에서 제외하지 않는다.

### 5.3 공개해도 유지할 금지선

- 크레딧 구매·판매·환전·양도·대여·재매입
- 현금, 암호자산, 상품, 경품, 역할, 권한, 서비스와의 교환
- Discord 구독, 서버 부스트, 후원, 광고 또는 유료 기능과의 연계
- 손실 만회·연속 참여를 자극하는 DM, 알림과 과장된 화폐 표현
- 연령·등급을 확인하지 않은 미성년자 대상 홍보
- 변호사·위원회·Discord 확인 범위를 넘는 다중 서버 확장

Discord 수익화 정책의 범위를 고려하면 KBO 정보 기능의 다른 수익화 가능성과
별개로 **크레딧 예측 기능과 그 운영 커뮤니티는 수익화 대상에서 계속
제외**하는 것이 안전하다.

### 5.4 가장 강한 대안

공개 버전에서는 **KBO 일정·결과·순위만 제공하고 크레딧 예측, 지급, 원장과
랭킹을 전부 비활성화**한다. 무료 단순 투표도 법률·등급 확인 범위가 명확해진
뒤에만 추가한다.

이는 공개 출시 시점을 앞당길 수 있고 도박 유사성, 게임물 등급과 미성년자
노출 위험을 가장 크게 줄인다. 대신 이번 KBO 제품의 핵심 참여 기능을
포기한다. “성인 역할 채널에만 노출”하는 안은 연령을 신뢰성 있게 검증하지
못하고 법적 분류 자체를 해결하지 않으므로 이 대안보다 약하다.

## 6. 결정 간 상호작용과 모순 점검

| 조합 | 점검 결과 |
| --- | --- |
| 일일 지급 50,000 + 일일 베팅 50,000 | 하루 지급 단위와 위험 노출 상한이 같아 설명 가능하다. 기존 잔액은 이월되지만 하루 소진 속도는 제한된다. |
| 건당 50,000 + 경기당 베팅 하나 | 한 경기 all-in은 가능하지만 같은 경기 양방향 hedge는 불가능하다. |
| 현재 잔액 랭킹 + 시즌 적중 랭킹 | 서로 다른 시간 범위를 이름과 화면에서 명확히 구분해야 한다. |
| 관리자 조정 포함 + 공개 표식 | 실제 잔액을 숨기지 않지만 표식이 낙인처럼 보이지 않도록 중립 표현을 사용한다. |
| 서버 탈퇴 즉시 비활성 + 열린 베팅 정산 | 새 처리는 막되 이미 수락한 베팅은 결과대로 끝내 정산 회피를 막는다. |
| 직접 연결 제거 + opaque 원장 1년 | 공개·직접 식별은 최소화하면서 정정·감사 기간의 원장 불변성을 유지한다. |
| 재연결 토큰 없음 + 신규 재가입 | 서버 재가입으로 과거 잔액·debt를 승계하지 않는 tradeoff를 명시적으로 수용한다. |
| 1년 원장 삭제 + 불변 원장 | 불변은 보존 중 update/delete 금지이고, 정해진 수명 만료 후 정책적 purge와 모순되지 않는다. |
| 30일 backup + 개인정보 삭제 | 운영 DB 삭제 뒤 backup에서 완전히 사라질 때까지 최대 30일의 지연과 복구 후 재삭제 절차가 필요하다. |
| 비현금 크레딧 + 법률·등급 gate | 비현금성은 위험 저감이지 면제 결론이 아니므로 gate를 제거하지 않는다. |

## 7. 소유자 승인과 재검토 이력

소유자는 2026-07-31 다음 권고안 전체를 승인했다.

> KBO 베팅 한도는 최소 1,000, 사용자·경기당 최대 50,000, KST 일일 총
> 50,000 크레딧으로 승인해. 금액은 1,000 단위이고 같은 KST 날짜에 공식
> 무효 환불된 금액만 당일 한도를 복원해.
>
> 보유 크레딧 랭킹은 현재 잔액 기준으로 시즌 간 유지하고, 결과 적중·정확
> 점수·적중률은 KBO 정규시즌과 포스트시즌을 분리해 시즌별 초기화해. 공식
> 정정은 과거 시즌 랭킹의 새 revision으로 반영해. 관리자 조정은 실제 보유액에
> 포함하되 공개 랭킹에는 `관리자 조정 포함`만 표시하고, 적중 랭킹에는
> 반영하지 마.
>
> 베팅 가입 해제나 서버 탈퇴 즉시 새 지급·베팅과 공개 랭킹을 중단하고 열린
> 베팅은 정상 정산해. 직접 식별 연결은 30일 복구용으로 보존하고 이후 최소
> 가명 연결과 사용자 단위 원장은 늦은 기준시각부터 1년 보존한 뒤 삭제해.
> 백업에는 최대 30일의 만료 지연과 복구 후 재삭제를 적용해.
>
> 크레딧 예측 기능 공개 전 한국 변호사 서면 검토, 게임물관리위원회 사전 확인,
> Discord 서면 정책 확인을 모두 필수 gate로 승인해. 하나라도 불명확하면
> 공개 버전은 KBO 정보 조회만 제공해. 아직 구현 계획이나 코드는 작성하지 마.

`건당 최대 10,000`, `완전한 시즌제 경제`, `조정 계정 시즌 보유액 랭킹
제외`, `즉시 복구 불가 비식별화`, `공개 버전 정보 조회 전용` 대안은
채택하지 않았다.

이후 소유자는 사용자용 베팅 탈퇴가 KBO 핵심 범위가 아니라고 재검토했다.
위 최초 승인문 중 세 번째 문단은 `OWN-048`로 대체됐고 현재 결정은 다음과
같다.

> 사용자용 베팅 탈퇴·복구 기능은 제외해. Discord 서버 탈퇴 즉시 새 지급·
> 베팅과 모든 공개 랭킹 노출을 중단하고 열린 베팅은 정상 정산해. 탈퇴 기록
> 뒤 표시명과 직접 Discord 연결을 제거하고 재연결 토큰은 만들지 마. Opaque
> 사용자 원장은 탈퇴와 마지막 KBO 원장 항목 중 늦은 때부터 1년 보존한 뒤
> 계정·남은 debt와 함께 삭제해. 서버 재가입은 명시적 신규 가입과 0 잔액으로
> 처리하고 backup 복구 뒤 탈퇴 상태와 연결 제거를 다시 적용해.
