# ADR

Read `AGENTS.md`, related policies, research, and Spike results.

Create or update an ADR using `docs/adr/TEMPLATE.md`.

1. Describe context and linked requirements.
2. Present realistic alternatives fairly.
3. State the recommendation and rationale.
4. Include positive and negative consequences.
5. Include security, operations, data, migration, rollback, and vendor lock-in.
6. Record rejected candidates and why.
7. Define conditions for reconsideration.
8. Keep the status `Proposed` unless the owner explicitly approved it.
9. Do not implement production code.

Report the ADR path, open owner decisions, and the exact approval or follow-up prompt.
