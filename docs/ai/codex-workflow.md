# Codex 작업 흐름

## 기본 원칙

Codex는 저장소 문서와 검증 가능한 증거를 근거로 작업합니다.

## 시작 시

1. `AGENTS.md`를 읽습니다.
2. `PROJECT_STATUS.md`를 읽습니다.
3. 작업과 관련된 정책, 운영 문서, 표준, ADR과 계획을 읽습니다.
4. 저장소 상태와 기존 구현을 확인합니다.
5. 요청이 어느 단계인지 분류합니다.

## 단계

### Research

- 요구사항과 제약 추출
- 현실적인 후보 비교
- 공식 문서와 1차 자료 우선
- 사실, 추론, 가정, 미확인 사항 구분
- 평가 기준과 의존성 기록
- 제품 코드 및 최종 기술 확정 금지

### Spike

- 한 가지 가설
- 명확한 성공 및 실패 기준
- 최소 범위
- 폐기 가능
- 결과와 재현 명령 기록
- 제품 코드로 자동 승격 금지

### ADR

- 상태는 먼저 Proposed
- 맥락, 후보, 결정, 장단점, 위험과 교체 조건
- 사용자 승인 전 Accepted 금지

### Implementation plan

- Accepted ADR만 근거로 사용
- 작은 검증 가능한 작업
- 파일과 테스트 범위
- 의존성과 롤백
- 아직 구현하지 않음

### Implementation

- 계획의 작업 하나만 수행
- 실패하는 테스트 또는 재현부터 시작
- 최소 구현
- 관련 테스트 실행
- 문서와 상태 갱신
- 다음 작업을 자동으로 넓히지 않음

### Review

- 요구사항 추적
- 오류, 보안, 데이터 손상과 회귀 위험 우선
- 테스트 누락
- 문서와 구현 불일치
- 근거 없는 완료 주장 금지

### Release

- 배포 전 점검
- 마이그레이션 및 백업
- 비밀정보
- OAuth와 도메인
- 모니터링
- 롤백
- 알려진 위험과 배포 판단

## 기술 조사 질문

기술을 고를 때 최소한 다음을 묻습니다.

- 어떤 요구사항이 이 결정을 필요로 하는가?
- 후보가 제약사항을 실제로 만족하는가?
- 공식 지원 상태와 유지보수 전망은 어떤가?
- 운영, 비용, 보안과 복구에 어떤 영향을 주는가?
- 가장 강한 대안은 무엇인가?
- 문서만으로 부족한 부분은 무엇인가?
- 어떤 Spike로 불확실성을 줄일 수 있는가?
- 어떤 조건이 생기면 결정을 바꿔야 하는가?

## 작업 종료 보고

- 변경 파일
- 결정 및 근거
- 가정과 미해결 항목
- 실행한 명령과 테스트
- 실패 사항
- 갱신한 문서
- 다음에 입력할 정확한 프롬프트
